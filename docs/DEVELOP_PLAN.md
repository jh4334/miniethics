# 디벨롭안 v2 — 적대적 검토 반영

v1(3관점 자문 종합)을 반박자 4명(기술 실현성 · 교육/아동 · 범위/우선순위 · 두 앱 비교)이 독립적으로 무너뜨리려 한 결과입니다. 반박 중 **코드·계산·빌드로 직접 확인된 것만** 반영했고, 확인하지 못한 것은 "추측"으로 표시했습니다. 에셋 트랙은 범위 밖입니다.

---

## 0. 검토 결과 한 줄

**v1은 "이 브랜치가 앱이다"라는 전제 위에 서 있었는데, 그 전제가 틀렸습니다.** 같은 저장소의 `main`에 같은 목적의 앱이 완성되어 배포 중이고, v1이 제안한 게임 재설계의 절반은 그 앱에 이미 구현되어 있습니다. 25개 항목보다 먼저 **어느 앱을 본체로 할지** 정해야 합니다.

### PR #17을 지금 머지하면 생기는 일 (빌드로 확인)

`index.html`(add/add)과 `README.md`가 충돌합니다. 충돌을 풀어도 `deploy.yml`은 `npm ci && npm run build`로 **A를 빌드**합니다. B의 `index.html`을 택하면 Vite가 B를 번들하되 B의 `sw.js`는 배포되지 않고 매니페스트 경로가 깨질 가능성이 높으며(추정), A의 에셋 30MB가 쓸모없이 함께 나갑니다. A의 `index.html`을 택하면 겉보기엔 A가 배포되지만 루트의 B 매니페스트가 A 앱에 링크되는 조용한 PWA 회귀가 생깁니다. **어느 쪽이든 Actions는 성공으로 끝나 문제를 알 수 없습니다.** 지금 PR #17은 머지하면 안 됩니다.

### 선택지

| | 내용 | 비용(추정) | 잃는 것 | 얻는 것 |
|---|---|---|---|---|
| **(1)** | A 본체, B의 강점만 이식 | 1~3일 | B 대부분 폐기. 아케이드 컨셉 회복 안 됨 | A의 정합성·에셋·테스트·배포·접근성 유지, 라이브 무중단 |
| (2) | B 본체, A 아카이브, Pages를 B로 교체 | 반나절 + B 로드맵 전부 | A등급 게임 9개, 에셋, 테스트, 오류 로그. 기존 태블릿 진행 기록이 화면에서 사라짐. PR #13·#16 고아 | 요구했던 컨셉, 빌드 없는 단순함 |
| (3) | 둘 다: A 루트, B `/arcade/` | 반나절~1일 | 두 앱 QA, "어느 게 작품인가" 혼란 | 아무것도 안 버림, 학급에서 A/B 실측 가능 |
| **(4)** | A 본체 + B를 "⚡1분 도전" 레이어로 흡수 + 이 문서를 A의 로드맵으로 | (1) + 2~4일 | 차시가 길어질 수 있음 → 1분 도전은 선택형 | 정합성 + 아케이드 감성을 한 URL·한 저장소·한 QA로 |

**추천: (4), 최소 (1).** (2)는 권하지 않습니다. 근거는 정합성 격차(9:2)와, B의 자체 개선안이 이미 A에 구현되어 있다는 사실입니다. B의 진짜 강점(짧은 루프, 터치 엔지니어링, 교사 해금, 이 검토 문서)은 파일 단위로 A에 이식 가능하고, B 게임의 `mount(host, ctx)`/`ctx.finish` 규약은 A의 `MiniGame` 인터페이스와 거의 같습니다.

단, **A가 완성품이라는 뜻은 아닙니다.** A의 3차시(개인정보 두더지잡기)와 12차시(퀴즈 랠리)는 C등급이고, 4차시가 "손가락 6개·단서 없으면 진짜"라는 최신 생성 이미지에 통하지 않는 휴리스틱을 가르치며(역오개념 위험), 백그라운드 전환 처리와 교사 해금·차시 상한이 없고, 확대 금지도 같습니다. 아래 판정표의 항목 대부분은 본체가 A여도 그대로 적용됩니다.

(3)은 "아케이드 컨셉이 타협 불가"이거나 아이들 반응을 실측해서 정하고 싶을 때의 임시안입니다. 어느 쪽이든 PR #13·#16은 A 기준이므로 본체를 A로 두면 먼저 검토·머지 여부를 정해야 합니다(#16이 접근성 항목 일부를 이미 다뤘을 수 있음 — 확인 필요).

판정: **유지 6 · 축소 13 · 후순위 2 · 삭제 4.** "안 하면 별일 없다"는 ★.

| # | v1 항목 | 판정 | 근거 (검토에서 확인된 것) |
|---|---|---|---|
| 1 | 교사 해금 버그 | **유지** | `unlockThrough`가 `cleared:true`를 찍어 진도·수료증 오염. `unlocked`/`cleared` 분리, 사용처 6곳 |
| 2 | 접근성 5종 | **유지(축소)** | 확대 허용·대비·reduced-motion·aria-label은 5줄 맞음. **키보드 조작은 게임 12개가 포인터 전용이라 5줄로 안 됨** → "게임은 터치 전용, 개념·퀴즈는 키보드 가능"이라고 정직하게 서술. iOS는 `user-scalable=no`를 애초에 무시하므로 이 모순은 안드로이드에서만 실제 발생 |
| 3 | 수업 모드(차시 상한) | 축소 | 기기 설정이면 태블릿 30대 × 매주 설정 = 10분/차시, 게다가 학생이 5탭 메뉴를 찾으면 스스로 올림. → **규칙형**: 차시별 `clearedAt` 기록, "마지막 클리어가 오늘이면 다음 차시 안 열림" 6줄. 교사 메뉴에 4자리 PIN |

| 6 | facts 배관 | 축소 | 소비자(8·12·13·20)가 없으면 죽은 배관. 9번은 게임 내부 `counts`로 충분. 계약 확장 자체는 5줄이니 **소비자가 생길 때** |
| 7 | 진행 코드 12~15자 | 축소 | 비트 계산은 맞음(60bit → base32 12자, v1 예시 `K3M9QX7T2B`는 10자로 부족). 그러나 **진도만** 담김. iPad 7일 삭제는 홈화면 설치로 이미 해결(README) → "진도 복구 전용"으로 역할 축소 |

## 4. 수정된 최소 실행 집합

본체 결정과 무관하게 먼저 해야 하는 것(반나절~2일):

1. **N1** 테스트 반입 + 태그
2. **1 + 2(축소)** 해금 버그 · 확대 허용 · 대비 · reduced-motion · aria-label
3. **3(규칙형)** 하루 한 차시 + 교사 PIN
4. **16(재작성)** 골든벨 오답 · OX 비율 · 7차시 문장 10개 — 전부 데이터 파일, 회귀 위험 0
5. **21 + 25** `discuss` · `teacherNote` 12차시분
6. **앱 밖**: 지필 사전검사(1차시 전주) · 동의 절차 · N4 동결일 확정

본체가 정해진 뒤:
- **A 본체**: PR #16 검토 → 3차시 교체(11번 축소안) → 백그라운드 처리 · 4차시 문구 → N2 파일럿 → 12차시 재검토
- **B 본체**: 9(3차시 시험) → 10(9차시 중패치) → 14(문장 재작성) → 13(재료 문장화) → N2 파일럿 → 나머지
- **(4) 흡수안**: A 본체 순서 + B의 g01/g03/g04/g05/g06/g08을 "⚡1분 도전"(선택형)으로 TS 변환

두 목표가 요구하는 순서가 다릅니다. **수업이 목표면** 위 1~5 다음이 22·23(읽어주기·천천히)이고 기록 인프라는 필요 없습니다. **대회가 목표면** 6(측정 설계)이 모든 것보다 먼저이고, 그다음이 8(QR)·18(딜레마 프로토타입)입니다.
