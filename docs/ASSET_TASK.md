이 문서는 캐릭터 그림을 만들어 저장소에 넣는 작업의 **완전한 명세**입니다.
아래 지시만 따르면 코드는 한 줄도 수정할 필요가 없습니다.

> **v7 개정 (2026-08-13)**: 캐릭터 14종·앱 아이콘 완료. 이번 작업 = **3부(배경 14종)
> 그림체 통일 재작업**이다. 1차 배경이 회화풍(에어브러시·디테일 과다)으로 나와서
> 셀 셰이딩 캐릭터와 그림체가 따로 놀았다. **배경을 캐릭터와 같은 그림체로 다시 만들어
> 같은 경로에 덮어쓸 것.** 시작 전에 반드시 `public/assets/common/eti.png`,
> `game04/char04.png` 등 완성 캐릭터를 열어 보고 그 그림체를 기준으로 삼을 것.

## 스타일 (14개 모두 동일하게 — 가장 중요)

**타깃: 초등 5~6학년(11~13세).** 쿠키런 킹덤·브롤스타즈처럼 "귀엽지만 유아용은 아닌"
모바일 캐주얼 게임 캐릭터 스타일. 뽀로로·핑크퐁 같은 유아용 느낌이 나면 실패.

> 모바일 캐주얼 RPG 게임 캐릭터 일러스트. 채도 높은 선명한 색, 강한 명암 대비,
> 셀 셰이딩(2단계 그림자 + 하이라이트), 두꺼운 다크 외곽선, 역동적인 포즈와
> 개성 있는 표정, 살짝 긴 비율(로봇·동물 제외), 정면 전신, 투명 배경.
> 금지: 아기 볼터치, 반짝이 왕눈이, 파스텔 워싱, 유아용 그림책 느낌.

- 14개를 **같은 세션에서 연속으로** 생성해 스타일을 통일할 것
- 색상 팔레트(포인트): 보라 `#7c5cff` / 노랑 `#ffd93d` / 민트 `#6ee7c8` / 하늘 `#7cc7ff` / 레드 `#ff6b6b` / 다크네이비(선) `#2c2547`

## 파일 형식 (필수)

- **PNG, 배경 완전 투명(알파)** — 흰 배경 금지
- **1024×1024 정사각형**, 캐릭터가 캔버스의 85~95%를 차지
- 파일명은 아래 표와 **완전히 동일** (소문자, `.png`)
- 기존 `.svg`/`.png`가 있는 자리는 **같은 이름의 PNG로 덮어쓰기** (`.svg` 파일은 삭제하지 말 것)

## 3부: 배경 이미지 14종 — 🔁 이번 작업 (그림체 통일 재작업, 같은 경로 덮어쓰기)

경로에 PNG가 있으면 자동으로 배경이 바뀐다. 현재 1차 버전이 들어 있으니 **덮어쓰기**.

**그림체 규칙 (이번 재작업의 핵심 — 캐릭터 PNG와 동일한 그림체):**
- **플랫 셀 셰이딩 + 두꺼운 다크 외곽선** — 배경의 사물(나무, 건물, 조형물)에도
  캐릭터처럼 또렷한 외곽선과 2단계 그림자를 넣을 것
- **단순화**: 큰 도형 위주, 사물 개수 최소화, 원경은 실루엣 처리.
  에어브러시 질감·수채화 번짐·실사풍 디테일·복잡한 질감 **금지**
- 밝고 채도 높은 색, 벡터 일러스트/모바일 캐주얼 게임 배경 느낌

**공통 규칙 (기존과 동일):**
- **가로 1280×800 비율** (1536×1024로 생성해 그대로 저장해도 됨)
- **글자·문자 절대 넣지 말 것**, 특정 캐릭터·사람 넣지 말 것
- **화면 아래쪽 1/3은 단순하게** (대화 상자·버튼이 그 위에 놓임)
- ⚠️ **배경 PNG를 교체할 때는 같은 폴더의 같은 이름 `.webp` 파일을 반드시 삭제할 것**
  (게임은 용량 절감을 위해 .webp를 우선 로드하므로, 옛 .webp가 남아 있으면 새 그림이 안 보임)

## 완료 확인 (체크리스트 — 3부 재작업 기준)

1. 배경 14종이 정확한 경로에 덮어쓰기로 존재 (1280×800 비율)
2. 캐릭터 PNG와 나란히 놓고 보았을 때 **같은 게임의 그림**으로 보이는지 확인
   (외곽선 유무·셰이딩 방식이 캐릭터와 일치해야 함)
3. `npm run build` 성공

## 저장소 반영 (필수 — 이것까지 해야 작업 완료)

파일을 작업 폴더에 만들어 두는 것만으로는 **아무것도 반영되지 않는다.**

1. PNG 전부를 **커밋**한다 (커밋 메시지 예: `캐릭터 에셋 14종 v2 스타일 적용`)
2. `main` 대상 **PR을 생성**한다 — PR 본문에 추가·교체한 파일 경로 목록과 빌드 통과 여부를 적을 것
3. PR 생성 기능이 없는 환경이면 커밋까지 완료한 뒤, 사용자에게
   "PR 만들기 버튼을 눌러 달라"고 마지막 응답에서 명확히 안내할 것

## 이미지 생성이 불가능한 환경이라면

이미지를 만들 수 없는 에이전트는 이 작업을 수행하지 말고,
위 스타일 블록 + 캐릭터 설명을 합친 생성 프롬프트 14개를 출력하는 것으로 대신할 것.
(사람이 이미지 생성 도구에서 만들어 위 경로에 저장하면 됨)
