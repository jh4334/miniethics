# 에셋 제작 작업 지시서 (이미지 생성 에이전트용)

이 문서는 캐릭터 그림을 새로 만들어 저장소에 넣는 작업의 **완전한 명세**입니다.
아래 지시만 따르면 코드는 한 줄도 수정할 필요가 없습니다.

> **v2 개정 (스타일 상향)**: 1차 에셋이 대상 학년(초등 5~6학년) 대비 너무 유아용으로
> 나와서 전면 재작업한다. 기존 `public/assets/**/*.png`를 **같은 파일명으로 덮어쓸 것**.

## 결과물 요약

아래 5개 파일을 **정확히 이 경로와 파일명**으로 생성해 넣는다 (기존 PNG 덮어쓰기):

| 저장 경로 | 캐릭터 | 설명 |
|---|---|---|
| `public/assets/common/hero.png` | 주인공 요원 | 11~12세 느낌의 사이버 요원. 4~5등신, 자신감 넘치는 표정과 포즈(주먹 불끈/씩 웃는 윙크), 고글을 머리에 올린 모습, 보라 재킷 + 노랑 포인트. 유치원생처럼 보이면 실패 |
| `public/assets/common/eti.png` | 가이드 로봇 '에티' | 매끈한 호버 로봇(다리 없이 떠 있음), 하늘색+흰색 바디, 머리에 노란 안테나, 검은 화면 얼굴에 민트색 스마일 이모티콘 눈. 스마트하고 믿음직한 인상 |
| `public/assets/game01/cookbot.png` | 요리사 로봇 '쿡봇' | 요리사 모자를 쓴 열정 셰프 로봇. 뒤집개를 힘차게 휘두르는 역동적 포즈, 주황/크림 바디, 바퀴 다리, 불꽃 이펙트 살짝 |
| `public/assets/game02/nyambot.png` | 과일박사 로봇 '냠봇' | 박사 학사모 + 둥근 민트색 바디. 과일을 향해 신나서 입을 크게 벌린 코믹한 표정. 아기 같은 볼터치 대신 익살스러운 열정 |
| `public/assets/game03/thief.png` | 악당 '정보도둑' | 보라색 그림자 몬스터 악당. 능글맞게 씨익 웃는 입, 도둑 안대 너머 반짝이는 눈, 정보 카드가 삐져나온 자루를 둘러멘 모습. 장난기 있는 라이벌 악당 느낌(공포 금지, 유아용 말랑함도 금지) |

## 파일 형식 (필수)

- **PNG, 배경 완전 투명(알파)** — 흰 배경 금지. 게임 배경 위에 바로 얹힘
- **1024×1024, 정사각형**, 캐릭터가 캔버스의 85~95%를 차지 (여백 최소화)
- 파일명은 위 표와 **완전히 동일**해야 함 (소문자, 확장자 .png)
- 기존 `.svg` 파일은 삭제하지 말 것 (PNG가 없을 때의 폴백으로 사용됨)

## 스타일 (5개 모두 동일하게 — 가장 중요)

**타깃: 초등 5~6학년(11~13세).** 쿠키런 킹덤·브롤스타즈처럼 "귀엽지만 유아용은 아닌"
모바일 캐주얼 게임 캐릭터 스타일. 뽀로로·핑크퐁 같은 유아용 느낌이 나면 실패.

> 모바일 캐주얼 RPG 게임 캐릭터 일러스트. 채도 높은 선명한 색, 강한 명암 대비,
> 셀 셰이딩(2단계 그림자 + 하이라이트), 두꺼운 다크 외곽선, 역동적인 포즈와
> 개성 있는 표정, 살짝 긴 비율(로봇 제외), 정면 전신, 투명 배경.
> 금지: 아기 볼터치, 반짝이 왕눈이, 파스텔 워싱, 유아용 그림책 느낌.

- 5개를 **같은 세션에서 연속으로** 생성해 스타일을 통일할 것
- 색상 팔레트(포인트 컬러로 사용): 보라 `#7c5cff` / 노랑 `#ffd93d` / 민트 `#6ee7c8` / 하늘 `#7cc7ff` / 레드 `#ff6b6b` / 다크네이비(선) `#2c2547`
- 캐릭터의 정체성(모자·장비·색 배치)은 위 표의 설명을 따르되, 구도와 포즈는 역동적으로 재해석할 것

## 완료 확인 (체크리스트)

1. 5개 PNG가 정확한 경로·파일명으로 존재
2. 각 PNG가 투명 배경인지 확인 (체커보드 위에서 확인)
3. `npm install && npm run dev` 실행 → 브라우저에서:
   - 타이틀 화면에 주인공+에티 새 그림이 보임
   - 1차시 스토리에 에티+쿡봇, 2차시에 냠봇, 3차시에 정보도둑이 새 그림으로 보임
4. `npm run build` 성공

## 저장소 반영 (필수 — 이것까지 해야 작업 완료)

파일을 작업 폴더에 만들어 두는 것만으로는 **아무것도 반영되지 않는다.**

1. 5개 PNG를 **커밋**한다 (커밋 메시지 예: `캐릭터 에셋 5종 PNG 추가`)
2. `main` 대상 **PR을 생성**한다 — PR 본문에 추가한 파일 5개 경로와 빌드 통과 여부를 적을 것
3. PR 생성 기능이 없는 환경이면 커밋까지 완료한 뒤, 사용자에게
   "PR 만들기 버튼을 눌러 달라"고 마지막 응답에서 명확히 안내할 것

## 이미지 생성이 불가능한 환경이라면

이미지를 만들 수 없는 에이전트는 이 작업을 수행하지 말고,
위 스타일 블록 + 캐릭터 설명을 합친 생성 프롬프트 5개를 출력하는 것으로 대신할 것.
(사람이 이미지 생성 도구에서 만들어 위 경로에 저장하면 됨)
